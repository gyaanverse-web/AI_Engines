# Question Skill Weightage Analysis Engine

This directory contains the modular, rule-based MVP for question skill weightage analysis. It accepts `question` and `chapter`, with an optional `use_ml` switch, and returns only the 10 required category percentages.

It now also includes a bootstrap ML pipeline that can:

- generate synthetic labeled training data
- train a lightweight local model artifact
- load the model during inference
- blend rule score and model score

## Endpoint

`POST /api/v1/question-analysis/analyze`

If served through the repository root app, the endpoint is exposed at:

`POST /context_and_step_itr2/api/v1/question-analysis/analyze`

## Request

```json
{
  "question": "Calculate the simple interest on ₹5000 at 5% per annum for 2 years.",
  "chapter": "Simple Interest",
  "use_ml": true
}
```

`use_ml` is optional:

- `true`: attempt rule + ML blending for this request
- `false`: force rule-only scoring for this request
- omitted: use server default behavior

## Response

```json
{
  "concept_based": 10,
  "formula_based": 35,
  "calculation_based": 50,
  "reasoning_based": 5,
  "memory_based": 0,
  "diagram_based": 0,
  "data_interpretation_based": 0,
  "proof_or_derivation_based": 0,
  "application_based": 0,
  "language_or_explanation_based": 0
}
```

## Modules

- `validator.py`: validates request payload
- `preprocessor.py`: normalizes question and chapter text
- `feature_extractor.py`: extracts deterministic signals
- `tokenizer.py`: tokenization used by the local ML pipeline
- `rules.py`: keyword-based scoring rules
- `chapter_mappings.py`: chapter default weights
- `scorer.py`: applies rules and future ML blending hook
- `normalizer.py`: guarantees integer output totaling exactly 100
- `ml_classifier.py`: model artifact loader and predictor
- `synthetic_dataset.py`: synthetic labeled dataset generator
- `ml_training.py`: local model trainer
- `config.py`: env/config helpers for ML enablement and artifact paths
- `question_skill_weightage.py`: orchestration entry point

## Synthetic Dataset

Generate a bootstrap dataset:

```bash
.venv/bin/python question_analysis/scripts/generate_synthetic_dataset.py
```

This writes:

- `question_analysis/data/synthetic_question_skill_dataset.jsonl`

Each line contains:

```json
{
  "question": "Calculate the simple interest on ₹5000 at 5% per annum for 2 years.",
  "chapter": "Simple Interest",
  "labels": {
    "concept_based": 6,
    "formula_based": 36,
    "calculation_based": 53,
    "reasoning_based": 3,
    "memory_based": 0,
    "diagram_based": 0,
    "data_interpretation_based": 0,
    "proof_or_derivation_based": 0,
    "application_based": 2,
    "language_or_explanation_based": 0
  }
}
```

These labels are bootstrap labels generated by the rule engine. They are suitable for cold-start training, not for final production-quality evaluation.

## Train the Local Model

Generate dataset and train model:

```bash
.venv/bin/python question_analysis/scripts/train_ml_model.py
```

This writes:

- `question_analysis/data/synthetic_question_skill_dataset.jsonl`
- `question_analysis/artifacts/question_skill_model.json`

## Enable ML Inference

By default, inference remains rule-only.

Enable ML blending:

```bash
export QUESTION_ANALYSIS_ML_ENABLED=true
export QUESTION_ANALYSIS_ML_MODEL_PATH=/home/roshan/Documents/vescavia_clients/EducationalAI/engines/question_analysis/artifacts/question_skill_model.json
```

Optional blend weights:

```bash
export QUESTION_ANALYSIS_RULE_WEIGHT=0.6
export QUESTION_ANALYSIS_MODEL_WEIGHT=0.4
```

The final inference path becomes:

```python
final_score = (rule_score * rule_weight) + (ml_score * model_weight)
```

The output is still normalized to:

- exactly 10 keys
- integer values
- total exactly `100`

## Notes on the ML Model

The local model is intentionally lightweight and dependency-free:

- chapter profile averages
- token profile averages
- feature profile averages

It does not call any LLM, external AI API, or hosted ML service.
